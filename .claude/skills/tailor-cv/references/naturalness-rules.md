# Naturalness rules

These are constraints, not preferences. The goal is a CV that a hiring manager reads as *well
suited* to the role, never as *written for* the posting. Those two things look different on the
page, and the difference is mechanical enough to encode.

A reader's suspicion is triggered by patterns, not by individual words. Each rule below kills one
pattern.

---

## 1. Substitute, never insert

Adopt the employer's vocabulary **only where it renames something already in the fact bank.**

The test: remove the JD from the table. Does the bullet still describe a thing that happened? If
yes, the substitution is honest. If the bullet only makes sense as an answer to the posting, it is
insertion — delete it.

✅ **Legitimate.** Fact bank says *"underwrite live loan applications, sizing debt against
collateral"*. JD calls this *"credit underwriting"*. Borrowing the noun is fair — it is the
employer's name for work already done.

❌ **Insertion.** JD asks for *"Argus Enterprise cash flow modelling"*. The fact bank has Excel
models and no Argus. Argus does not appear in the CV. Not in the skills list, not in a bullet, not
hedged as "exposure to". It goes to `notes.md` as a gap.

❌ **Insertion by adjacency.** JD asks for *"institutional LP reporting"*. The fact bank has
reporting to a fund principal. These are not the same and "institutional" does not get borrowed.

The subtlest failure is the plausible one. A term that *could* apply, that the candidate *might*
have done, is exactly the term that collapses in an interview.

## 2. Saturation cap

- Alter **at most ~60% of bullets** across the CV.
- Leave **at least one bullet in the most relevant role completely untouched.**
- Never alter every bullet within a single role.

Real CVs are uneven. They contain lines written two years ago for a different purpose, lines the
author is fond of, lines that only partly fit. A document where every bullet points at the same
posting reads as generated even when every fact in it is true — the *uniformity* is the tell, not
the content.

Track the count. If a tailoring run wants to touch more than the cap, that is a signal the role is
a stretch, not a signal to raise the cap.

## 3. Lever priority

Work down this list. Stop as soon as the JD's priorities are reflected. Do not reach for a lower
lever because an upper one feels insufficient.

1. **Reorder bullets within a role.** Zero detectability — bullet order carries no truth claim. The
   first bullet in each role is what gets read; putting the right one there is most of the job.
2. **Select which bullets survive.** The one-page limit means choosing. Cutting the least relevant
   bullet is invisible and frees space.
3. **Reorder the skills list.** Same reasoning; the list is already a set, and sets have no
   canonical order.
4. **Swap synonyms.** Per rule 1.
5. **Re-angle emphasis.** Same facts, different lead clause. A bullet that opens on the modelling
   can open on the credit decision instead, if both are true and in the fact bank.
6. **Promote a buried fact-bank detail.** Surface something real that was cut from the baseline for
   space, because this posting makes it relevant.

Writing a bullet from scratch is a **last resort**, and only ever as a recombination of fact-bank
entries. If a run reaches step 6 and still can't match, the honest output is a gap note.

## 4. Voice fingerprint

Extracted from the baseline. Preserve all of it — register mismatch is the second-most-common tell
after keyword stuffing.

- **Verb-first bullets.** "Underwrite…", "Build and stress…", "Executed…", "Managed and
  validated…". Never "Responsible for…", never "Successfully…", never a noun-phrase opener.
- **Tense by recency.** Present tense for current roles (Meridian), past for finished ones
  (Coriats, Baker Tilly, TCI Rent operational period).
- **British spelling.** *modelling*, *summarised*, *organising*, *analyse*, *programme*. Not
  *modeling*, *summarized*, *organizing*.
- **Numeric style.** `\$20m+`, `\$100M+`, `\pounds30k+`, `30+`, `34-unit`. Keep the existing
  conventions rather than normalising them — the inconsistency is human.
- **Density.** Roughly one quantified figure per bullet *on average* — meaning some bullets carry
  two and some carry none. Do not give every bullet a number.
- **Length.** Baseline bullets run ~20–40 words, most wrapping to two rendered lines. Match it.
- **Punctuation.** Semicolons to join related clauses within a bullet; em-dashes (`---`) sparingly;
  no bullet ends without a full stop.
- **No intensifiers.** The baseline contains no "significantly", "substantially", "highly",
  "extensive". Do not introduce them.

## 5. No structural additions

The layout is settled and does not move to accommodate a posting:

- No summary, profile, or objective line. (Decided explicitly — the header stays as-is.)
- No "Core Competencies", "Key Skills", or keyword block.
- No new sections, and no reordering of existing sections.
- No bolding for emphasis inside bullets. Bold is currently used only for the dissertation label
  and affiliation names; keep it that way.
- **No additions to Technical Skills.** That list may be *reordered* to lead with what the posting
  cares about. Nothing joins it that isn't already there unless the fact bank contains it *and*
  Francois has confirmed the proficiency.
- **Typography is fixed.** Any new construct matches the type and spacing scale in `CLAUDE.md`
  rule 2. Never vary size, weight, or spacing to give a tailored bullet more presence — emphasis is
  earned by position and content, never by formatting.

## 6. No title inflation

Covered in `immutables.md`, restated because it is tempting: the posting's job title never migrates
into the experience section. Not in the title field, not smuggled into a bullet as "acting as…" or
"in effect the…".

## 7. The cold-read test

Before writing output, read the tailored CV start to finish as though seeing it for the first time
and without the JD in mind. Ask:

- Does any sentence read as though it exists to satisfy a requirement?
- Does any paragraph suddenly change register?
- Would this document make sense as an application to a *different* firm in the same sector?

The third question is the sharpest. A well-tailored CV should still be a good general CV. If it
only works for this one posting, it has been over-fitted — revert until it works for both.
